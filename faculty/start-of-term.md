# IT 140 Faculty Start-of-Term Reorientation

Use this page whenever you begin teaching an IT 140 section, especially if you did not teach IT 140 in the immediately preceding term.

The goal is to reestablish the **current** course workflow without requiring you to reread every technical document.

## 1. Open the Current Course

Confirm that you can access:

* your assigned IT 140 course in D2L Brightspace;
* Instructor Resources;
* the Module One setup content; and
* the current assignment/project Guidelines and Rubric pages.

D2L Brightspace remains authoritative for graded activity requirements, submissions, grading, deadlines, and instructor feedback.

## 2. Check Current Course Technical Status

Before relying on repository or setup information remembered from a previous term, check:

* [IT 140 Course Status](https://github.com/GC-STEM/it140/wiki/Course-Status)
* [Main IT 140 Repository](https://github.com/GC-STEM/it140)
* [Module One Setup Tasks](https://github.com/GC-STEM/it140-m1-setup-tasks)

The main repository's activity table shows the current course repository links and development/release status.

> [!IMPORTANT]
> Do not assume that a repository, setup command, artifact version, or release state is unchanged because you used it in a previous term.

## 3. Confirm Your Faculty Course Environment

The CVD is the IT 140 reference environment.

If your faculty CVD has not been configured, was reset, or you are unsure of its state, use
[Faculty Setup and Familiarization](setup-and-familiarization.md).

A local faculty installation can be useful but is optional. Faculty should understand the CVD workflow even when they prefer to work locally.

## 4. Review the Student Setup Path

Students encounter the Module One setup sequence before later repository work.

Review the current [Module One Setup Tasks](https://github.com/GC-STEM/it140-m1-setup-tasks) so you recognize:

* the GitHub account readiness step;
* the CVD setup and verification process;
* the optional local setup choice;
* successful verification checkpoints; and
* where students are directed when setup fails.

You do not need to memorize platform-specific technical repair procedures.

## 5. Review Only the Current Activity Repositories You Need

Before students reach an assignment or project:

1. Open the activity repository from the live main-course repository.
2. Read the top-level `README.md`.
3. Review the current D2L Brightspace Guidelines and Rubric.
4. Note the required student deliverables and any starter files.
5. Note the repository's Help/Support, Issues, Discussions, Wiki, or test resources when present.

See [Course Repository Architecture](../shared/course-repository-architecture.md) for the canonical repository map.

## 6. Refresh the Support Boundaries

Remember the basic routing model:

* **Faculty** — assignment interpretation, grading, instructor feedback, and instructional support.
* **Academic Support** — programming learning, academic coaching, written feedback, English-language support, and related student-support services.
* **LSS** — IT 140-focused programming learning and problem-solving assistance through workshops/office hours and related resources.
* **IT Service Desk** — technical environment, access, account/authentication, and supported tooling problems.
* **Academic Advisors** — academic planning and broader advising concerns.
* **Course technical maintainers** — reproducible defects in course-managed technical content.

Within Academic Support:

* programming-learning questions may go to faculty, LSS, or 24/7 Drop-In Tutoring;
* time/task prioritization, organization, technical-reading strategies, and related academic-process needs may go to Academic Coaching.

See [Academic Support for IT 140](../academic-support/README.md) and [Support Boundaries](../shared/support-boundaries.md).

## 7. Remove Old Assumptions, Not Necessarily Old Files

If you have older local repositories from a previous term:

* do not treat them as the current course source of truth;
* do not give students copied commands from those old repositories;
* use the live GC-STEM course templates and READMEs for the current term; and
* keep old faculty/test copies only if they are useful to you and clearly distinguishable from current work.

For a student repeating IT 140, see [Repeat Students](../shared/github-workflow.md#repeat-students).

## Reorientation Complete

You are ready to support the current term when you can answer:

* Where are the current graded requirements? **D2L Brightspace**
* Where is current course/repository status? **IT 140 Course Status**
* What is the reference development environment? **CVD**
* Where are current activity procedures? **The live activity README**
* Where do technical environment failures go? **IT Service Desk**
* Where do code-learning questions go? **Faculty / Academic Support**
* Where do time/task, organization, or technical-reading needs go? **Academic Coaching**
* Where do academic-plan concerns go? **Academic Advisor**

Return to the [Faculty Support Guide](README.md).
