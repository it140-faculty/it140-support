# IT 140 Academic Support | 24/7 Drop-In Tutoring

Use this page when you are **referring an IT 140 student to 24/7 Drop-In Tutoring, coordinating with tutoring personnel, or preparing course context that will help a tutor support the student efficiently**.

This is an F&S-facing guide. Student-facing instructions for how to request help should remain in the official Academic Support experience and, where useful, in IT 140 student-facing repositories or wikis.

## Important Context About the Tutoring Service

24/7 Drop-In Tutors work for **Tutor.com and are not SNHU employees**. They can provide general tutoring support, including Python, but they should not be expected to have particular knowledge of:

* IT 140;
* SNHU assignment wording or rubrics;
* current IT 140 GitHub repositories;
* the course IDE/CVD setup;
* IT 140 starter files or tests; or
* the current module's instructional sequence.

This makes **current course context** particularly important when the student's question depends on an IT 140 activity.

Official student access:

[24/7 Drop-In Tutoring](https://lhh.tutor.com/SNHU/PreSession)

## Good Fits for 24/7 Drop-In Tutoring

Tutoring can be a strong option for help with general introductory Python and problem-solving topics such as:

* input and output;
* variables and data types;
* type conversion;
* strings;
* arithmetic expressions;
* decision branching;
* loops;
* functions;
* lists;
* dictionaries;
* interpreting Python syntax/runtime errors in student-created code;
* testing small examples;
* tracing program logic;
* debugging strategy; and
* breaking a programming problem into smaller steps.

The tutor should generally help the student understand and develop **their own solution**, not produce a complete graded deliverable.

## Course Context F&S Can Provide or Locate

When a Tutor.com tutor lacks IT 140 context, F&S can point the tutor or student to the **public source that supplies the missing course context**.

| Information the Tutor May Need | Where F&S Can Find It |
| --- | --- |
| Course and level | IT 140 is an introductory Python course; prior programming experience is not assumed |
| Current activity purpose and workflow | The public activity repository's top-level `README.md` |
| Starter file or provided example | The public activity repository |
| Current programming concepts | Current Brightspace module and zyBooks; use the public repository only where it identifies relevant concepts |
| Exact graded requirement or rubric | Current D2L Brightspace Guidelines and Rubric; faculty interprets requirements |
| Student's intended behavior | Ask the student what they are trying to make their own work do |
| Actual behavior | Exact error, output, or unexpected result from the student's work |
| Student-created code/work | Share only through an approved support channel; do not make a private student repository public |
| Course technical environment problem | IT Service Desk, not tutoring |

## IT 140 Learning Progression

A tutor can avoid introducing unnecessary complexity when F&S identify approximately where the student is in the course.

| Stage | Main Learning/Development Focus |
| --- | --- |
| Module Two | Foundational input/output, variables, data types, type conversion, strings; first small Python program |
| Module Three | Program design and decision branching through a paycheck flowchart and pseudocode |
| Module Four | Branching, loops, and input validation through higher/lower game pseudocode |
| Module Five / Project One | Requirements, game-world design, flowcharts/pseudocode, and planning a text-based adventure game |
| Module Six Milestone | Lists/dictionaries and a simplified room-navigation prototype using a gameplay loop, branching, validation, testing, and debugging |
| Module Seven / Project Two | Integrating functions, dictionaries, gameplay loop, branching, input validation, testing, and debugging into the full game |

When helping an IT 140 student, prefer the **simplest approach that matches concepts the student has reached**. A technically valid advanced Python solution may not be appropriate learning support for an introductory student working in an earlier module.

For a full topic sequence, see the current course/zyBooks materials.

## Academic-Integrity Boundary

Appropriate tutoring can include:

* explaining a programming concept;
* asking the student to predict what code will do;
* tracing a small section of the student's logic;
* interpreting an error;
* helping the student design a test;
* asking questions that lead the student to the next step;
* demonstrating a concept with a different or partial example; and
* helping the student compare expected and actual behavior.

Tutoring should not become:

* a complete solution to a graded IT 140 assignment or project;
* a finished flowchart or pseudocode deliverable for the student;
* a rewrite of the student's program into a submission-ready solution; or
* an interpretation of whether the work earns a particular rubric score.

See [Support Boundaries](../shared/support-boundaries.md#academic-integrity-boundary).
