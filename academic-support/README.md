# IT 140 Academic Support Guide

This guide is for **SNHU faculty and staff (F&S)** who refer IT 140 students to Academic Support, coordinate support across services, or provide Academic Support directly.

Although this repository is public, this page is **not written as a student-facing service page**. When referring a student, use the current official Academic Support entry point or course link rather than asking the student to navigate this F&S support repository.

> [!IMPORTANT]
> Use this page to select the Academic Support service that best matches the student's need. For assignment requirements, grading, or technical failures, use the non-Academic-Support routes identified below.

## Academic Support Services for IT 140

| Student Need | Best-Fit Academic Support Option | IT 140 Context |
| --- | --- | --- |
| Course-specific Python instruction or live group Q&A | [IT 140 - Intro to Python Workshop / IT Basics Office Hours](../lss/README.md) | LSS can work from current IT 140 concepts, repositories, and course workflow |
| Quick, on-demand help with general Python concepts or debugging | [24/7 Drop-In Tutoring](tutoring.md) | Tutor.com tutors can support Python but do not have particular knowledge of SNHU courses |
| Time/task prioritization, organization, reading technical directions, academic-skill development, critical thinking/problem solving, or learning strategies | [Academic Coaching](coaching.md) | Coaching can address how the student approaches the course without becoming programming tutoring or technical support |
| Writing development for an IT 140 written deliverable | Written Feedback | Useful for writing quality; not for checking Python, pseudocode, flowcharts, or rubric compliance |
| English-language learning support | ELL/ESOL options across Academic Support | Support may be available through tutoring, LSS sessions, coaching, and ARC resources |

A student may appropriately use more than one service. For example, a student who is behind because they wait until the weekend and also does not understand loops may benefit from **Academic Coaching** for time/task planning and **LSS or 24/7 Drop-In Tutoring** for programming learning.

## IT 140 in 60 Seconds

Academic Support personnel do not need to become IT 140 instructors to support students effectively, but these facts help explain the course context:

* **Course:** IT 140 - Introduction to Scripting.
* **Length:** Eight weeks.
* **Programming language:** Python.
* **Prior experience:** Previous programming experience is not required.
* **Workload context:** A three-credit course in this format should require about **16 hours per week on average for an average student**.
* **Pace:** Programming concepts build from week to week; early delays can compound.
* **zyBooks:** A significant part of weekly learning and practice, especially early in the course.
* **Development environment:** The Codio Virtual Desktop (CVD) is the reference environment; supported local setup is optional.
* **GitHub:** Public course repositories provide instructions/templates; students create private repositories for development work.
* **Graded requirements:** D2L Brightspace Guidelines and Rubric remain authoritative.

For more context, use:

* [IT 140 Course Overview](../shared/course-overview.md)
* [Course Glossary](../shared/glossary.md)

## Workshops and Office Hours

Learning Support Specialists (LSS) provide IT 140-related live group support.

Current IT 140-related sessions include:

* **IT 140 - Intro to Python Workshop** — a workshop format with instruction and student questions; and
* **IT Basics Office Hours** — question-driven live support without a fixed agenda.

Use the [LSS Support Guide](../lss/README.md) when you need F&S guidance about:

* what LSS should know about the current course;
* appropriate programming help;
* workshops and office hours;
* course tools and repositories;
* academic-integrity boundaries; or
* LSS referrals and escalation.

Use the current [group-session schedule](https://snhuacademicresourcecenter.screenstepslive.com/a/1834032-group-sessions-schedule-workshops-office-hours-and-peer-groups) for current times.

## 24/7 Drop-In Tutoring

24/7 Drop-In Tutoring is useful when a student needs general Python or problem-solving help without waiting for a scheduled IT 140 session.

The important distinction for F&S is that 24/7 Drop-In Tutors work for **Tutor.com and are not SNHU employees**. They therefore should not be expected to know:

* the IT 140 module structure;
* the current Brightspace assignment wording;
* the course GitHub workflow;
* the IT 140 CVD setup;
* which starter files are current; or
* how an IT 140 rubric should be interpreted.

F&S can make tutoring more effective by helping the tutor reach the **current public course context** rather than expecting the tutor to know the course.

See [24/7 Drop-In Tutoring | IT 140 Context for F&S](tutoring.md).

## Academic Coaching

Academic Coaching has strong potential to support IT 140 because many programming difficulties are partly about **how students organize, read, plan, and work through unfamiliar problems**.

Useful coaching areas include:

* time and task prioritization;
* reading and following technical documentation;
* strengthening academic skills;
* support strategies for learning differences;
* critical thinking and problem solving; and
* organization across an eight-week technical course.

Coaches do not need to teach Python or troubleshoot Git/GitHub to be useful. They need enough course context to help the student build a workable process and recognize when a problem should move to another support role.

See [Academic Coaching | IT 140 Guide for F&S](coaching.md).

## Written Feedback

Written Feedback may be appropriate for the relatively small amount of formal writing in IT 140.

Examples include:

* the **Module Two IDE Features Reflection**; and
* the **Project One text-adventure game theme/storyline description**.

Written Feedback can help with areas such as:

* organization;
* clarity;
* paragraph development;
* sentence-level writing; and
* communicating technical ideas to a reader.

Written Feedback should **not** be used as a substitute for:

* checking whether Python code works;
* validating pseudocode or a flowchart;
* determining whether a deliverable meets an IT 140 rubric criterion;
* interpreting an assignment requirement; or
* grading.

For rubric or requirement interpretation, refer to the student's **IT 140 instructor and current D2L Brightspace Guidelines and Rubric**.

## English-Language Learning Support

English-language learners may be able to receive support through multiple Academic Support pathways, including:

* 24/7 Drop-In Tutoring;
* LSS Workshops and Office Hours;
* Academic Coaching; and
* [ARC English Language Learner resources](https://snhuacademicresourcecenter.screenstepslive.com/m/126487).

Treat ELL/ESOL support as a **cross-service pathway**, not as a separate IT 140 technical-support function.

For a student whose main barrier is understanding technical English, it may be useful to combine language support with the course-reading strategies in [Academic Coaching](coaching.md#reading-comprehension-and-technical-documentation).

## When Academic Support Is Not the Primary Route

| Need | Primary Route |
| --- | --- |
| What does the assignment require? What must be submitted? | IT 140 faculty + current D2L Brightspace Guidelines and Rubric |
| Grade, rubric application, deadline, or instructor feedback | IT 140 faculty |
| CVD, VS Code, Python environment, GitHub authentication, repository creation/clone/recovery, or Verify failure | IT Service Desk |
| Academic plan, course sequence, program requirements, or broader persistence concern | Academic Advisor |
| Public IT 140 repository/starter/test/script/documentation appears defective | Course technical maintenance path |

See [Support Boundaries](../shared/support-boundaries.md) for the canonical routing model.

## Privacy and Academic Integrity

Because this repository is public, do not place student-specific information, private repository contents, or graded student solutions here.

When Academic Support personnel work with a student:

* use approved channels for student work;
* preserve the student's authorship and decision-making;
* support learning rather than completing graded work for the student; and
* route assignment-interpretation questions to faculty.
